# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Timezone-naive datetime manipulation, fails across overnight shifts, lacks instant second-truncation (R1), and checks `minutes > 10` rather than elapsed seconds `> 600`. | Punching in at 09:40:01 with timezone offsets or overnight shift (e.g. 22:00-06:00) computes shift start relative to the wrong calendar date (today instead of yesterday) or crashes. | Normalized instants to UTC, converted to IST calendar coordinates, resolved shift start against attendance date, enforced `diff_sec > 600`, and floored whole minutes. |
| 2 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round()`, which applies round-half-to-even (banker's rounding) and floating point approximation instead of round-half-up (R4). | For durations producing values like 2.675 hours, Python `round(2.675, 2)` evaluates to 2.67 rather than 2.68. | Used `decimal.Decimal` with `ROUND_HALF_UP` to round `(punch_out - punch_in).total_seconds() / 3600` to 2 decimal places. |
| 3 | `compute_overtime` (lines 44-48) | Omits the minimum 30-minute threshold requirement (R3) and miscalculates shift end date for overnight shifts. | Punching out 15 minutes after shift end returned 15 instead of 0. For overnight shifts (22:00 - 06:00), `date_str` references yesterday's date, calculating overtime against yesterday's 06:00 (~24 hours of false overtime). | Implemented `diff_minutes >= 30` threshold check, and advanced shift end date by +1 day when `shift_end <= shift_start`. |
| 4 | `health` (lines 72-74) | Unconditionally returns `{"status": "ok"}` without checking MongoDB connectivity. Contract requires 200 only if MongoDB answers a ping; else 503. | Stopping MongoDB service still resulted in `/health` returning HTTP 200 OK. | Executed `client.admin.command("ping")` within try/except block; raises `HTTPException(503, "Database unavailable")` if ping fails. |
| 5 | `create_employee` (lines 77-85) | Check-then-insert race condition (`find_one` then `insert_one`), lacks schema validation (code regex, shift equality, string lengths), and returns unformatted datetime instead of epoch ms. | Concurrent creation requests with identical `emp_code` both pass `find_one` and insert duplicates. Providing `shift_start == shift_end` or code "USER123" succeeded with 201 instead of 422. | Enforced database unique index on `emp_code` and caught `DuplicateKeyError` to return 409; added Pydantic validators for formats and `shift_start != shift_end`; returned `created_at` as integer epoch ms. |
| 6 | `list_employees` (lines 88-96) | Pagination skip offset is calculated as `page * page_size`, skipping items 1-20 when `page=1`; `total` counts whole collection ignoring department filter; missing ascending sort on `emp_code`. | Requesting `page=1&page_size=20` returns page 2 results; filtering by department reported total count of all employees in the database. | Fixed skip calculation to `(page - 1) * page_size`; passed query filter `q` to `count_documents(q)`; added `.sort("emp_code", 1)`; validated pagination parameters (`page >= 1`, `1 <= page_size <= 100`). |
| 7 | `punch_in` (lines 99-121) | Unhandled missing employee crashes with 500 `TypeError`; check-then-insert race condition; uses server local timezone instead of IST; ignores overnight shift calendar date rules (R1); accepts unvalidated status/timestamps; includes forbidden `id` field in response; does not serialize `punch_in` to epoch ms. | Calling punch-in for unknown `emp_code` returns 500; concurrent punch-ins insert duplicate records; overnight shift punch-in before shift end assigns current day instead of previous day; response includes MongoDB ObjectId string `id`. | Verified employee exists (404); relied on database unique compound index on `(emp_code, date)` and caught `DuplicateKeyError` to return 409; resolved attendance date using IST and overnight rules; truncated timestamps to whole seconds; validated status enum and epoch ms ranges; formatted output strictly to OpenAPI schema without `id`. |
| 8 | `list_attendance` (lines 124-150) | Memory exhaustion / scalability flaw: loads entire collection into memory (`list(db.attendance_logs.find(q))`), sorting and slicing in Python; sorts only by date desc; missing `date_from > date_to` validation (422); returns illegal `id` field; missing epoch ms serialization. | On 100,000 documents, query loads all documents into RAM causing high latency and OOM; passing `date_from > date_to` returned 200 instead of 422; ties on date were not sorted by `emp_code` asc. | Implemented database-side pagination and sorting `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)` backed by compound index; added 422 validation for invalid date ranges; removed `id` field; serialized timestamps to epoch ms. |
| 9 | Startup Indexes (General architecture) | No indexes were created at startup. Database only had default `_id` index, preventing unique constraint enforcement and forcing full collection scans (`COLLSCAN`) on queries. | Database allowed duplicate employee codes and attendance dates; queries and aggregations performed `COLLSCAN` in explain output. | Configured FastAPI `lifespan` handler to idempotently create unique indexes on `employees.emp_code`, `attendance_logs.(emp_code, date)`, and query indexes for listings and aggregations. |

### Non-defects examined and decided fine

- **`load_dotenv(override=False)`**: Loading local `.env` with `override=False` ensures developers can configure local environments while ensuring real system environment variables injected by grading pipelines take absolute priority.
- **`IST = timezone(timedelta(hours=5, minutes=30))`**: Standard fixed-offset timezone representing Indian Standard Time without Daylight Saving Time adjustments, matching statutory requirements.
- **Default shift values (`09:30` and `18:30`)**: Correctly matches the default shift boundaries defined in the OpenAPI specification.
